# 2. 설계

## 2.1 원칙

1. **데이터가 중심** — 모든 화면은 "실험 1건 = 표의 1행"이라는 하나의 표 위에서 동작한다.
2. **변수는 전사 공통** — 열 이름(변수)은 프로젝트가 아니라 시스템 전체에 하나만 둔다. 프로젝트마다 다르게 적힌 이름은 별칭(alias)으로 흡수한다.
3. **설치 최소** — Python 표준 라이브러리로 서버를 띄우고, ML은 `numpy`/`scikit-learn`이 있을 때만 켜진다(없으면 설치 안내).
4. **화면 4개** — 프로젝트 · 데이터 · 예측 · 설계. 그 밖의 기능은 넣지 않는다.
5. **예측은 항상 근거와 함께** — 학습 건수, 교차검증 점수, 불확실성, 범위 밖 경고를 숨기지 않는다.

## 2.2 데이터 모델 (`data.json`, version 2)

```jsonc
{
  "version": 2,
  "variables": [            // 전사 공통 변수 사전
    {"id": "v01", "name": "나노입자 함량", "unit": "wt%", "kind": "composition",   // composition | process | property
     "aliases": ["NP", "입자 함량"], "desc": ""}
  ],
  "projects": [
    {"id": "p01", "name": "WF-C70 세라믹 IR 차단형", "product": "차량용 윈도우 필름", "owner": "김개발",
     "status": "진행", "stage": "2차 R/A",             // status: 진행 | 보류 | 완료,  stage: 자유 문자열
     "note": "", "specs": [{"var": "v09", "spec": "≥70"}],   // 규격: ≥70, ≤1.5, 70~80, 100±5
     "created": "2026-01-10", "updated": "2026-10-12"}
  ],
  "experiments": [          // 프로젝트에 매달리지 않고 평평하게 둔다 → 통합 표가 곧 이 배열
    {"id": "e0001", "project": "p01", "date": "2025-11-03", "label": "DOE-1", "note": "",
     "source": "manual",    // manual | import:<파일명> | migrated | candidate
     "values": {"v01": 14, "v02": 30.8, "v09": 68.7},
     "excluded": false}     // 점검에서 제외한 실험은 ML에 쓰지 않는다
  ]
}
```

- 값은 숫자만 ML에 쓴다. 문자열 값은 표에 보이지만 모델에는 들어가지 않는다.
- 변수 `kind`가 `property`인 것이 예측 대상(Y), 나머지가 입력(X)이다.

## 2.3 모듈 구성

```
server.py          HTTP 서버 (표준 라이브러리), 라우팅만
lab/
  store.py         data.json 읽기/쓰기, 모델 검증, id 발급, 원자적 저장
  dataset.py       통합 표 만들기(X/Y 행렬), 규격 파싱·판정, 통계, CSV/XLSX 내보내기
  importer.py      CSV/XLSX 읽기, 열 이름 → 변수 자동 매핑(정규화·별칭·유사도)
  ml.py            정방향 모델 학습/예측, 역방향 탐색, 민감도, 유사 실험
  migrate.py       v1 data.json → v2 변환
xlsx_writer.py     기존 xlsx 작성기 (유지)
index.html         화면 전체 (HTML/CSS/JS 한 파일, 외부 의존 없음)
tests/             unittest
docs/              문제정의, 설계, 발표자료
```

| POST/PATCH/DELETE | `/api/variables[/{id}]` | 변수 생성·수정·삭제(사용 중이면 거부), `merge`로 두 변수 합치기 |

| GET | `/api/dataset?fmt=csv\|xlsx` | 통합 표 내려받기 |
| POST | `/api/ml/train` | 학습 시작(백그라운드, 데이터 스냅샷). 상태는 `/api/ml/status`의 `training` |

| POST | `/api/ml/inverse` | 규격 → 조성 후보 |
| POST | `/api/ml/pareto` | 두 성능의 트레이드오프 전선(파레토) |
| POST | `/api/ml/explore` | 다음 실험 추천(모델이 가장 불확실한 조성) |
| POST | `/api/ml/sensitivity` | 한 변수를 움직일 때 한 성능의 변화 곡선 |
| POST | `/api/ml/similar` | 입력 조성과 가장 가까운 과거 실험 |

접근 제어는 v1과 같다(기본 localhost, `--lan`이면 사설망, `--readonly`면 쓰기 차단).

## 2.5 ML 설계

### 정방향 (조성 → 성능)
- 성능 변수마다 별도 모델. 결측이 있는 행은 그 성능의 학습에서만 뺀다.
- 입력 행렬 = [숫자 입력 변수 | 문자열(범주형) 입력 변수 one-hot | 프로젝트(제품군) one-hot]. 범주형은 값이 대부분 문자열이고 2~20가지 수준일 때 자동 인식.
- 후보: `RandomForestRegressor`, `GradientBoostingRegressor`, `Ridge`(2차 다항 특성). 5-fold CV로 R²·MAE를 재고 R²가 가장 높은 것을 채택. 학습 건수가 8건 미만이면 그 성능은 "학습 불가"로 둔다.
- 불확실성: ±구간 = √(CV 잔차 분산 + RF 트리 분산). 채택 모델이 RF가 아니어도 보조 RF를 두어 "모델이 자신 없는 정도"(epistemic)를 입력마다 잰다.
- 외삽 경고: 입력값이 학습 데이터 min~max를 벗어나면 변수별로 표시한다.
- 변수 중요도: permutation importance(모델 종류와 무관하게 같은 방식).

### 역방향 (규격 → 조성)
1. 사용자가 규격(≥, ≤, 범위, 목표±허용)을 성능별로 입력하고, 고정하고 싶은 입력 변수를 잠근다.
2. 잠기지 않은 변수는 데이터 범위(min~max) 안에서 Latin Hypercube로 2,000점을 뽑는다.
3. 각 점의 성능을 정방향 모델로 예측하고 점수를 매긴다: `Σ 규격 위반량(정규화) + λ·불확실성 + μ·데이터와의 거리`.
4. 상위 20점을 국소 섭동으로 30회 개선하고, 서로 다른 후보 5개를 돌려준다(가까운 후보끼리는 하나로 합침).
5. 각 후보에 예측 성능·구간·규격 판정·가장 가까운 실제 실험을 붙인다. "실험으로 등록" 버튼으로 바로 계획 실험이 된다.

### 트레이드오프 (파레토)
- 목표 두 개(최대/최소)와 규격·고정 조건을 받아 데이터 범위 안 3,000점을 예측하고, 규격을 만족하는 점 중 지배되지 않는 점(파레토 전선)을 최대 12개 돌려준다. 전선 점은 예측 화면으로 보내거나 실험으로 등록할 수 있다.

### 다음 실험 추천 (능동 학습)
- 규격·고정 조건을 지키는 후보 중 모델 불확실성(트리 분산 평균) + 데이터와의 거리가 큰, 서로 다른 조성 n개를 돌려준다. 이 실험을 하면 모델이 가장 많이 배운다.

### 유사 실험
- 입력 변수를 표준화한 뒤 유클리드 거리로 가까운 k건을 보여 준다. 모델이 없어도 동작한다.

## 2.6 화면

| 화면 | 보여 주는 것 | 주요 동작 |
|---|---|---|
| 프로젝트 | 카드 목록(상태, 규격 달성 여부, 실험 수, 최근 실험일) → 상세(규격, 실험 표) | 프로젝트 추가, 규격 편집, 실험 한 줄 추가, 표 안에서 바로 수정, 엑셀 붙여넣기/가져오기 |
| 데이터 | 전 프로젝트 통합 표, 입력→성능 산점도, 변수별 요약(건수·평균·범위), 변수 사전, 점검 | 필터, 정렬, 내려받기, 변수 이름·단위 통일(합치기), 제외 |
| 예측 | 입력 변수 폼(기본값=중앙값) → 성능 카드(예측, ±구간, 규격 판정), 민감도 그래프 | 학습 버튼, 모델 점수 보기, 유사 실험 |
| 설계 | 규격 입력(프로젝트에서 자동 채움), 고정 변수 → 후보 5개 | 추천, 후보를 실험으로 등록 |
